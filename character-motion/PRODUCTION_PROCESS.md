## Draft loop

1. Work on one character and one walk direction. Reuse its reviewed idles. Keep original/rejected sources and exact prompts in the existing provenance ledger; do not create additional historical binding ledgers after every direction.
2. Build each source revision into a new private staging directory with the existing shared builder.
3. Run `python tools/review_character_motion.py <build-manifest>` with the calibrated `--base-speed`, `--pixels-per-frame`, and (when runs exist) `--run-base-speed`/`--run-pixels-per-frame`. It reviews walking, running and idle through the existing motion auditor AND Sprite Doctor's actual per-sheet checks. Missing sibling directions are not required for this draft check. Doctor code and framing contracts participate in cache keys; failed results stay failed when cached. It outputs contact/opposing sheets and normal/half-speed gait GIFs. It never grants semantic acceptance, installs assets or substitutes for final full-set/identity/runtime validation.
4. Visually examine opposing contacts FIRST. Reject same-foot cycles immediately, before spending time on palette polishing, browser capture or provenance re-audits. Then review all phases, identity/equipment and playback. Do not regenerate for optional cosmetic differences that already satisfy the stated acceptance requirements.
5. Maximum two corrective generation calls for one failure mode/direction. Stop after 20 minutes of a direction trial without a viable canonical loop. Do not reset either limit on continuation, rename the failure, or silently increase limits. Record failure and request a method change. These are stop rules, not permission to accept bad art.
6. Keep stdout compact: counts, changes and actionable failures. Read large report bodies only to investigate a specific finding. Update the existing progress checkpoint once per meaningful outcome; no per-character Python review/verification clones.

- Keep run sources in a separate `runs` build-manifest map. A run motion spec explicitly supplies `run_gait`, eight distinct `run_animation` mappings, canonical contact/load/flight/reach labels, and positive distance-based timing.
- `ground_clearance` is an eight-integer, symmetric flight envelope: contact/loading are zero, flight/reach are positive and bounded to 5% of frame height. The builder preserves the clearance; audits check the corrected ground anchor. Sprite Doctor bounds flight-related visible-height changes by this same declared clearance while keeping contact, walk and idle limits unchanged. Do not use this to waive walking faults or accept an unreviewed run.
- Strict semantic review requires separate run contact sheets, normal/half previews, source hashes and six explicit run review flags. Numerical passes never fill those flags.
- Layered authoring is retained as hash-bound `derivations`, not invented image-generation prompts. Inputs must trace through earlier derived records to original prompt artifacts; masks, rigs and normalization tooling are retained. Never mirror asymmetric bodies or equipment to synthesize missing views.
